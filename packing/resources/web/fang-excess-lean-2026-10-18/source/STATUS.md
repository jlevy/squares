## Lessons

* The first version (no X-sort cutoff, 3 chunks of 115 rows for n = 343) took 972 s wall but only
  47 s user under heavy load; with the cutoff the pair work drops ~7–9×.
* Chunk statements must use numerals: `headsOK D 82 (L.drop (82 * 4))` checks in ~2 s,
  `headsOK D k (L.drop (k * 0))` with `k` a `def` took 24 s for the same work.
* Data and chunk files import only `Sqlean.CheckCore` (core Lean): ~0.4 s startup and < 1 GB
  per process instead of a Mathlib import per chunk.

## Not done / possible next steps

* The interface is integer-scaled (`⟨X, Y, C, S, N⟩` with a global `D`) rather than a literal
  `List (ℚ × ℚ × ℚ)`; this is a faithful encoding of the rational certificates and much cheaper in
  the kernel. A `ℚ` front end could be added if wanted.
* Nothing is published; de Winter's 211 data is gitignored and regenerated by
  `scripts/fetch_211.sh`.
