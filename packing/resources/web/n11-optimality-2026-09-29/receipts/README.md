# Receipts of the Eleven-Square Optimality Packet

A receipt is the record of one checker run: its verdict, the SHA-256 of every input
object and of the checker's own bytes, the command and commit that produced it, and a
replay script. The proof's composer reads a fixed set of receipts by hash and checks
that their joins agree, so the composed proof can be re-verified in seconds without
rerunning the geometry, whose 2.1 GB of upstream inputs are not in this repository. Git
holds the evidence; the hashes bind it (OR-16).

Not every receipt is read by the composer. Some are the ancestry an accepted receipt
cites as its input; some are controls that measure what a partial, refused or profiling
run reports; some are superseded attempts kept beside their replacement so the record
says why the replacement exists; some are data the checkers read; and two are the
retained replacement components of the review of 2026-10-03, which stand beside the
accepted components rather than in their place. The tier column says which, and the
binding column says who reads it, derived from the receipts themselves.

This file is generated by `packing/devtools/render_n11_receipts_register.py`;
`packing/tests/test_n11_receipts_register.py` fails when a receipt is undocumented or
the file is stale. Edit the curated purposes in the renderer, then rerun it.

## How the Binding Column Is Derived

- **composer, pinned**: the final composer reads it at a hash fixed in its own modules:
  `FIXED` in `packing/devtools/inventory_n11_completion.py`, or the pinned field
  inventory, nonfield manifest and exclusion inventory.
- **capture join** and **pilot registry**: `CAPTURE` or `PILOTS` in the same modules
  names it as one capture node's or one case's accepted execution.
- **exclusion inventory**, **baseline inventory**, **field inventory**: a recorded
  execution path in `exclusion-inventory.json`,
  `baseline-d4-cuts/baseline-execution-inventory.json` or
  `field-batch-a/field-coverage-inventory.json` falls inside it.
- **cited by result hash** and **cited by path**: another receipt's text contains the
  SHA-256 of its `result.json` (stored or decoded; for a top-level file, the file
  itself), or the path `receipts/<name>`.
- **object held**: another receipt cites, by hash, an object stored under its `objects/`
  that the citer does not store itself.
- **paper** and **validation guide**: the review article's template, or the packet's
  `VALIDATION.md` or `README.md`, links it.

Each citing receipt is listed once, under the strongest relation, and a citation that
only restates a structured binding, such as the inventory naming a batch or the
composer's own output files, is not repeated. Text means every `.json`, `.jsonl`, `.sh`,
`.txt`, `.md` and `.log` file and every `.json.gz` decoded; a `.json.gz` over 2 MB on
disk is a retained source state, not a record of a run, and is not read. Not read:
`capture-root-pilot/adaptive-source.json.gz`.
