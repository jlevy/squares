## The Degree-672 Polynomial at $n = 83$

`facts/n-083.json` retains both forms of the polynomial:

- `roots[0].coefficients` is the complete primitive 673-integer coefficient array,
  highest degree first and with positive leading coefficient
- `roots[0].polynomial` is the complete formatted equation
- `roots[0].index` is the source’s root index, 27

The formatted equation has 343,204 characters, so this README does not duplicate it.
The extractor established:

- irreducibility over the rationals from the intersection of modular factor-degree
  constraints:
  - modulo 100003: `1^2 3 75 145 447`
  - modulo 100019: `2 16^2 34 272 332`
  - modulo 100043: `1 5 6 7 8 11^2 252 371`
- one real root in an exact interval of radius $10^{-308}$ around the full decimal
  centre retained in `checks[0].isolated_root`
- agreement with the SVG’s 100-digit side, Evan Daniel’s 38-decimal KKT value, and the
  frontier’s 14-decimal printed value

The degree exceeds the extractor’s configured Sturm-sequence limit, so it did not
independently count the source’s root index 27. The verified statement is that the
printed polynomial is irreducible and has one root in the retained interval.
It does not prove that the SVG’s geometry realizes that root or that the packing is
globally optimal.

## Reproduction

Run from `packing/`, with the project interpreter and the task’s external scratch
variables:

```bash
packet=resources/web/kingbird-exact-side-facts-2026-10-07
uv run --frozen python -m devtools.extract_kingbird_svg_exact svg 55 --out "$packet/facts/n-055.json"
uv run --frozen python -m devtools.extract_kingbird_svg_exact svg 71 --out "$packet/facts/n-071.json"
uv run --frozen python -m devtools.extract_kingbird_svg_exact svg 83 --out "$packet/facts/n-083.json"
uv run --frozen python -m devtools.extract_kingbird_svg_exact svg 126 --out "$packet/facts/n-126.json"
uv run --frozen python -m devtools.collect_kingbird_historical_polynomials --check

numeric_n='68 103 105 110 131 132 152 154 155 156 180 181 182 207 208 209 210 236 238 239 240 241 268 270 271 272 273 297 301 303 304 305 306 307'
audit_out=$(mktemp -d "$TMPDIR/kingbird-numeric-svg-audit.XXXXXX")
for n in $numeric_n; do
  out=$(printf '%s/n-%03d.json' "$audit_out" "$n")
  set +e
  uv run --frozen python -m devtools.extract_kingbird_svg_exact svg "$n" --out "$out"
  status=$?
  set -e
  if [ "$status" -ne 1 ]; then
    printf 'n=%s returned status %s; expected 1; inspect %s\n' \
      "$n" "$status" "$audit_out" >&2
    exit 3
  fi
  if [ ! -s "$out" ]; then
    printf 'n=%s returned status 1 without a nonempty fact file: %s\n' \
      "$n" "$out" >&2
    exit 3
  fi
done
printf 'replay facts retained in %s\n' "$audit_out"
```

The extractor exits zero when it finds and verifies side polynomials and exits two for
an acquisition refusal. Exit one is broader: it can represent a source with no verified
side polynomial, an unverified root, or an uncaught parse error.
For each numeric replay, inspect the printed counts and retained arrays to confirm that
`statements`, `solver_calls`, `roots`, and `checks` are empty, then compare its source
hash with the archived entry in `acquisition/sources.json`.
New mathematical content requires review even when the command returns one.
The replay leaves its output in task scratch for inspection; do not delete it from the
script.
