# Verification guide

## Statement checked

The certificate proves that every unit square contained in
`[0,4456575/1000000]^2`, at every orientation, contains at least one of the 16
listed rational points strictly in its interior. The piercing/pigeonhole and
compactness argument in [`PROOF.md`](PROOF.md) then gives

```text
s(17) > 4456575/1000000 = 4.456575.
```

## Level 1: audit the archived proof

```bash
bash ./verify_archived.sh
```

This checks the frozen SHA-256 and runs three exact implementations on the
archived 21,696,657-byte certificate:

- fast exact C++;
- independent Boost arbitrary-precision C++;
- independent Python arbitrary-integer checker.

Expected final marker:

```text
ARCHIVED_CERTIFICATE_VERIFIED_4P456575
```

On the preparation machine this was the convenient reviewer path: it avoids
regenerating a 21.7M-node tree while still independently recomputing every leaf
claim.

## Level 2: deterministic full reproduction

```bash
bash ./verify_4p456575.sh
```

This additionally:

1. compiles the deterministic generator;
2. regenerates the complete tree in a temporary directory;
3. requires the generated certificate to have SHA-256
   `5fbee90dc6fedc1851e4b8b9866f8ffa41c38cb09ebb6a9f748096217f078550`;
4. checks the same hash for the archived certificate;
5. compares generated and archived files byte-for-byte with `cmp`;
6. runs all three exact checkers on the regenerated bytes.

Expected final marker:

```text
ALL_EXACT_CHECKS_PASSED_4P456575
```

The generator is substantially more work than simply checking the archive, so
reviewers who only want to audit the theorem can use Level 1 first.

## Level 3: malformed-input tests

```bash
bash ./tests/rejection_tests.sh
```

The script requires the fast checker to reject truncated data, trailing data,
and an invalid root opcode.

## Trust boundary

The point-search procedure, generator, and certificate bytes are untrusted.
Certificate acceptance depends only on the exact checker predicates.

The fast checker shares low-level routines with the generator for speed. The
Boost and Python checkers independently spell out the theorem-critical
arithmetic with arbitrary-size integers. All strict comparisons remain strict
after exact denominator clearing.

No floating-point arithmetic, numerical optimizer, nonlinear solver, random
search, SAT/SMT solver, or interval-arithmetic package is needed to verify the
frozen claim.

## Compilers

The frozen reproduction was checked with GCC. The scripts accept another C++17
compiler through `CXX`, e.g.

```bash
CXX=clang++ bash ./verify_archived.sh
```

The theorem-critical arithmetic is integer-only; cross-compiler agreement is an
additional implementation check, not an assumption of the proof.
