## Receipt Policy Addendum

The first S2 fix added digests of repository-generated facts and certificate bytes.
This review initially accepted that fix, then corrected the recommendation after
checking
[OR-16 and OR-18](../../../operating-rules.md#or-16-use-git-for-repository-integrity-reserve-checksums-for-real-trust-boundaries).
Those files are repository-owned data; an external-download exception would not justify
their self-pins. The final implementation removes both digests, without an integrity
allowlist entry or a higher guard baseline.

The replacement records `n`, the exact side, unit-square side, representation, scalar
kind, coordinate frame and complete ordered corner/id roster.
Rational spellings are normalized before both decisions and comparison.
Native `exact-algebraic` dispatch is enforced separately.
Geometry changes invalidate an old receipt, while equivalent rational spellings,
formatting and nongeometric provenance or replay prose do not.
The regression suite exercises both directions.

The SHA-256 values for original external source bytes remain acquisition provenance.
Git supplies the history of the generated facts, certificates and receipts; the checker
does not resolve or compare Git revisions.
Complete semantic recertification and replay passed after this replacement.
The new packet’s compressed-fact inventory also uses paths and square counts, without
digests of its generated files.
The older archived inventories are unchanged.

## Security Surface

The untrusted inputs are source JSON bytes and their metadata.
Admission is bounded to one million input bytes, 324 squares and 256 characters per
rational literal.
The retained gzip reader bounds both compressed and decompressed facts.
JSON objects reject duplicate keys.
The source note is length-bounded and discarded.
The full semantic certification receipt and decompressed corner certificates have a
separate four-million-byte ceiling; checker rational strings are bounded to 1,024
characters. The source admission ceiling remains unchanged.
No source field is evaluated as Python, substituted into a command, or used to choose an
output path.

Output paths are constructed from fixed repository roots and the admitted counts.
Writes use the existing atomic-output helper; temporary witness files use private
temporary directories.
The changed paths add no network requests, credential handling, dependency installation
or execution of downloaded code.
The operator supplies local acquisition paths; this is a repository CLI, not a service
accepting remote path arguments.
The existing exact checkers remain part of the trusted implementation.

## Design and Publication Boundary

The adapter reuses the existing rational parser and half-angle conversion, then checks
its serialized output with the two existing geometry implementations.
This avoids a third packing verifier.
Its fixed source roster and explicit release/supplement keys fit this import; admitting
another source requires a deliberate change to that roster and its provenance contract.
No materially better bounded design was identified.

The registration change can contain source facts, attribution, reported records and
atlas drawings checked at their exact rational sides.
The subsequent confirmation change must carry the complete receipts, derived
certificates, both accepting reviews and the explicit evidence and verified-bound
updates. A checked drawing alone supplies no result-confirmation rung.
The exact packing receipts establish upper bounds, with no local or global optimality
claim or reproduction of the producer’s checker.
The separate numerical motion screen only supplies the stated findings about the
retained configurations.

The packet README, retained comparison, source coverage and the mathematical review
state the source scope and exact-versus-displayed distinction.
The atlas adapter’s docstring correctly calls the source decimal a finite display:
several submitted displays are farther above the exact fraction than nearest rounding
would produce.
