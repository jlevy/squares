# Workbench Consumer and Legacy-Task Inventory

This is the Phase 0 inventory for `think-a9gt` at integrated commit `27d2f8cc`. It
implements the disposition rules in the
[workbench plan](../specs/active/plan-2026-09-11-workbench-from-spike-to-product.md) and
uses the findings in the
[architecture review](review-2026-09-12-workbench-stack-architecture.md).
The destination is the top-level `packages/workbench/` package.
Every newly introduced workbench file belongs there, including files added during
repair.

The current v2 tree contains 211 tracked files: 23 Python entry points or helpers, two
browser assets, 180 JavaScript probes, one probe declaration, one probe guide, one HTML
template, two generated data/views, and the retained notes.
The tree is both a live publication source and a research record.
Location under `spikes/` therefore does not prove that a file is dead.

## Disposition Rules

The tables use four dispositions:

- **Move** means the file’s live responsibility moves into `packages/workbench/`, with
  no second implementation left behind.
- **Replace** means a smaller package contract, test, or tool preserves the observable
  behavior; the old entry point stays until its named consumers use the replacement.
- **Retain** means the file is evidence or a research record and remains available even
  after production stops reading the spike tree.
- **Remove** means `think-cqfc` may delete the file only after the replacement and
  no-consumer conditions in this inventory are proved.

Git retains prior implementations and generated bytes.
The working tree retains records and the instruments still required to reproduce them;
it does not retain duplicate live application engines for historical interest.

## Executable Consumer Graph

The current publication route is:

1. [build_candidate.py](../../../packing/atlas/known-best/video/spikes/v2-transitions/build_candidate.py#L1718)
   reads all 324 witnesses and renderings, the known-best manifest, the composite
   record, kpress fonts and KaTeX support, then inlines the template, CSS, JavaScript,
   and payload.
2. [build_workbench_site.py](../../../packing/devtools/build_workbench_site.py#L91)
   invokes that script with `--all`, selects its `workbench.html`, adds the site note,
   and writes `packing/site/workbench/index.html`.
3. [pages.yml](../../../.github/workflows/pages.yml#L321) runs the site builder and
   uploads `packing/site`.

Two live tools consume the published-shape artifact directly:

- [capture_video.py](../../../packing/devtools/capture_video.py#L44) drives the page’s
  `pairs`, `select`, `duration`, `seek`, `gapBar`, `setMode`, and `setCapture` methods
  and writes a video plus receipt.
- [bench_annealing.py](../../../packing/devtools/bench_annealing.py#L351) loads the same
  page, calls its seeded `physics` API, independently checks and repairs returned poses,
  and streams trials to the annealing result directory.

The browser checkers and the older measurement tools also load generated HTML and drive
`window.atlasTransitions`. The declaration at
[atlas-transitions.d.ts](../../../packing/atlas/known-best/video/spikes/v2-transitions/probes/atlas-transitions.d.ts#L449)
is therefore a consumer contract, although the browser never loads it.

### Publication Input Gap

[RENDER_INPUTS](../../../packing/devtools/build_workbench_site.py#L43) declares seven
paths, but the invoked builder reads the 324 witnesses, 324 renderings, composite
record, kpress assets, and `devtools.render_explainer` described above.
It also declares the tracked `transition-stats.json`, although the invoked builder
regenerates that file in its scratch output and the site builder does not read the
tracked copy. [test_explainer.py](../../../packing/tests/test_explainer.py#L470) proves
only that Pages filters cover the declared list and that each declared path exists; it
does not prove that the list is the builder’s true input closure.

`think-g0lh` must replace this hand-maintained partial list with the package build’s
actual input contract and update both Pages filter blocks.
A change to any witness, rendering, catalogue record, font/input tool, package source,
or lockfile that can alter the page must select and rebuild the artifact.
A negative contract test must demonstrate that omitting one representative input class
fails.

## Verified Shipped Behavior

The current source already provides these prototype behaviors, which migration tests
must hold:

- Pack and Animate are visible controls in `template.html` lines 67–69.
- Pack excludes the illustrative tween at `workbench.js` lines 6298–6316.
- A mode switch stores mode-local selection, stops the old run, clears stale optimizer
  state, and restages the destination mode at lines 6668–6740.
- Pack starts with all `n` squares on stage, and Animate starts on the first pair in its
  range at lines 6724–6736.
- Restart has distinct Pack and Animate behavior while preserving current settings at
  lines 6769–6795.
- Previous, random, grid, and best-known initial conditions appear in `template.html`
  lines 105–109 and are implemented by `INITIALS`/`setInitial` at `workbench.js` lines
  4123 and 4736.
- `setSeed` is part of the runtime API and invalidates the current run/cache at lines
  6435–6452 and 6930–6931. The declaration does not yet include it, and the floating
  `withSeed` mix at line 4167 aliases integers before the documented 32-bit coercion;
  `think-gxxc` and `think-dq1l` remain required.

On this audit, the current site builder reproduced a deterministic, self-contained 4.4
MB page and `check_probes.py` reported 180 parsing, function-valued, reached probes.
The primary browser checker could not launch Chromium inside this audit sandbox because
macOS denied the browser rendezvous port; this is an environment refusal, not a checker
verdict. The prior architecture review records a passing primary checker, and
`think-kpvc` still must put a bounded equivalent on the PR surface.

## Migration Exit Conditions

`think-l9z0` may start from this inventory without moving legacy source.
Broad extraction starts only after `think-109t` records the repair checkpoint.
For each old entry point, `think-g0lh` records its replacement command/import, direct
consumers moved, and parity evidence.
Temporary wrappers name their consumer and deletion condition.

`think-cqfc` can finish only when all of these are true:

1. Pages, build, CI, capture, benchmark, documentation, and campaign reproduction routes
   use package sources or an explicitly pinned historical commit.
2. Every probe group above maps to a package assertion or an explicit rejected stale
   expectation.
3. `rg` finds no production import, subprocess call, workflow input, default page path,
   or documented live command that depends on the v2 source tree.
4. The retained notes, generated views, negative findings, and their provenance remain
   discoverable.
5. The production build contains one simulation kernel and one animation timeline; no
   old page, benchmark, or tab carries a copied engine.
