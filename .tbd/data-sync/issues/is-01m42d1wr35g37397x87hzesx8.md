Owner direction, 2026-10-04: git SHAs should not be baked in as a matter of process, and checksums are kept only where an integrity check crosses a real trust boundary (OR-16; tbd guidelines general-coding-rules, Cryptographic Hash Checks). Current practice bakes commit SHAs in at several points. DATA_REVISION is re-pinned to a commit in its own commit after every data merge; this is a large source of merge churn and conflicts. Session gates certify a declared commit and check its ancestry. check_provenance requires recorded engine commits to be reachable, and records cite branch commits. Inventory each use, name what failure it actually catches, and propose removing or replacing (content or regenerated-result comparison) every use that crosses no trust boundary. Keep checksums for downloaded artifacts (for example the release asset holding PR 307's dumps) and for certificates distributed for independent checking. Owner decision before any removal.
