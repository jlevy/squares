A generated JSON file of citations per n for the stage: for the current lower and upper bound of each n, the value it cites, who established it (authors and year for a published or external source, this project for its own), and a concise academic reference line. Built from packing/frontier/results.yaml (priority, previously-published, source_key), packing/frontier/evidence.yaml (source, source_key) and the literature archive under packing/resources, never typed in. Needs a schema, a drift check that fails when the register changes and the JSON does not, and tests over recorded register entries. Omit an n's line where the register has no number or no attributable source, and say which in the generator's report rather than guessing.

## Notes

Survey (2026-09-21, read-only, by a sub-agent) for the citation data. Summary; the full text is in the session transcript.

Chain today: packing/frontier/n-NNN.md -> packing/devtools/build_composite_figure_data.py -> packing/atlas/known-best/composite-figure.json -> build_candidate.load_facts (lines 1059-1161) -> facts.ts. Upper = reported_upper_bound; lower = verified_lower_bound (shown unless status proved); star = a novel first-party lower-bound evidence entry. Composite, frontier records and the built page agree on all 324 values; stars at n = 11, 12, 18, 19, 20, 21.

Sources: per-case reported_upper_bound (found_by, found_year, improved_by, source_key), reported_lower_bound (proved_by, proved_year, source_key), evidence.yaml entries (novelty, performed_by, source_key). Bibliographic data (authors, year, title, venue) exists only as Markdown tables in packing/resources/README.md (papers 189-219; web 491-523 has no authors or years). Needs a structured bibliography keyed by source_key, or a parser.

Pitfalls: an evidence entry's source_key can be a checker's lineage, not the bound's author (E-fractional-interval-decision, E-n011-threshold-net1440-interval-decision cite Burns-Massaccesi); rule: any novel first-party entry makes the bound the project's, else the previously-published entries must share one key or the build fails. found_by is sometimes the catalogue's "Proved by" credit on grid packings (13, 22, 23, 24, 33, 34, 35, 46). Key spellings drift across files ([Schadt n=29 repository] vs [Schadt n29 2025]; [Stromquist Memo I 1984] vs [Stromquist Memo I]). Paths come in three roots. Kleddamag is deliberately not registered for n = 17.

Coverage: upper 177 grid, 19 external certified here, 79 external reported, 6 UnitSquare reported (certificate missing), 43 catalogue-only with no finder, 0 project. Lower 290 Nagamochi 2005, 3 area or center counting, 17 perfect squares (cited to Nagamochi), 8 external papers or projects (5, 6, 10, 13, 17, 22, 33, 46), 6 project (11, 12, 18, 19, 20, 21), 0 missing.

Proposed format: one line per bound, "Surname(s) Year, short venue"; & for two authors, et al. for three or more; "in Friedman & Ellsworth, Squares in Squares" for catalogue constructions; "This project 2026, result T-NNN" for our own. Measured examples 38-66 characters.

Proposed file: packing/atlas/known-best/bound-citations.json with a schema, generated by packing/devtools/build_bound_citations.py (--update, --check), registered in validate_schemas and the known-best records gate step.
