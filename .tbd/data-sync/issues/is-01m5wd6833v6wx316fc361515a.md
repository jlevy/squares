The owner's asks, 26 October 2026, in one epic.

1. The detailed log of changes is reachable only as `CHANGELOG.md` on GitHub, and the
   `#changelog` bookmark lives on `news.html`. Give the changelog its own page on this
   site, so News and Changelog are each a page of their own.
2. Put Overview, News and Changelog under a Project menu in the navigation bar.
   Overview stays the homepage, `./`, and keeps The Squares Project as its title and
   link preview.
3. The News page's closing action row gains a button to the on-site Changelog.
4. The Changelog links the GitHub issues and pull requests behind each entry.
5. Rewrite the homepage's Recently Added introduction to the owner's wording:
   "A log of all results recorded by the Squares Project since <date>. For major items
   only, see News."
6. A tally of results is never set in the toggles' small caps: one style everywhere,
   the count bold and its noun lowercase (`17 results`), and the disclosure toggle sits
   on the first line when a summary wraps.
7. "House best packing" is confusing in reader text; the point is a new record.

Closeout follows the standard release process: the validation tiers, a pull request that
leads with what the branch cost, hosted CI green, then a `packing/site-changelog.yaml`
entry after the merge. A site-only change is never a release candidate
(`development.md`, Maintaining the project changelog).
