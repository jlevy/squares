SYSTEMIC SOUNDNESS ISSUE in the original database, not in any upstream source.

Every optional field in packing.reported_upper_bound is typed as 'value or null' with no vocabulary for WHY a value is missing. Null therefore collapses at least five distinct states:

  1. the source states it and we transcribed it
  2. the source states it and we MISSED it (transcription defect)
  3. the source is silent, so nothing is claimed either way
  4. the source is silent and the fact is genuinely unknown to mathematics
  5. the fact is not applicable to this case

A reader, or a renderer, cannot tell these apart, and two live defects came directly from that.

EVIDENCE, all verified in this repo:

rigid (boolean|null; 4 true, 42 false, 54 null). It is non-null exactly where catalogue_pictured is true, so false encodes 'the catalogue pictured this and did not write Rigid' -- state 3 -- while READING as state 'this packing is not rigid'. Taken at face value the record says n=1 is not rigid: a single unit square exactly filling a 1x1 container, which cannot move at all. n=4 and n=9 likewise. n=16,25,36,49,64,81,100 are null though equally trivially rigid. The upstream catalogue is sound here: it annotates rigidity for four packings, is silent otherwise, and NEVER asserts non-rigidity anywhere (zero occurrences of any negative phrasing in resources/web/kingbird-squares-in-squares.md). The collapse is entirely ours.

exact_form / algebraic_degree / minimal_polynomial (16 / 89 / 89 nulls). n=54 was state 2: Kingbird prints s = 7 - (1/2)sqrt(2) + sqrt(1+sqrt(2)) at kingbird-squares-in-squares.md:292 and we recorded null, because that is the only n<=100 entry rendered as a multi-line begin{aligned} block. It was encoded identically to n=55, which is state 3 or 4. A published figure consequently badged n=54 'only known numerically'. Fixed, but only because someone questioned a neighbouring case.

Other nullable fields with the same ambiguity: source_date (98), found_year (54), analytically_optimized (52), tilt_angles_deg (42).

WHY THIS IS SERIOUS: these records are the repository's representation of best-known knowledge, and downstream consumers reasonably read them as such. A null that means 'we did not look' is indistinguishable from one that means 'mathematics does not know', so absence of evidence silently renders as evidence of absence. Every figure, table and claim built on these fields inherits that.

DONE WHEN: each optional fact carries an explicit status alongside its value -- minimally stated-by-source / not-stated-by-source / not-transcribed / derived-here / unknown -- and the schema requires it; the 100 existing records are re-derived against the retained sources under that vocabulary; and a check fails when a field is present without a status. Related: think-k5z2 (no reparse of exact forms), think-de1s (rigid specifically), think-n3j4 (n=11 regression), think-d1qd (assurance naming, the same confusion one layer down).

INTERIM MITIGATION already in place: the composite figure derives rigidity from perfect-square geometry plus catalogue annotation rather than trusting the stored flag, and its badge is labelled 'rigid (established)' so absence reads as not-established rather than not-rigid. docs/project/specs/active/spec-2026-08-27-composite-figure-fact-sourcing.md records the sourcing rules.
