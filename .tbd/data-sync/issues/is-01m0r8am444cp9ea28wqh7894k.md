Confirmed on merged main. Raised by the PR #15 review as part of F-17; confirmed independently and it is worse than stated, because the false claim is in this repo's own comment.

test.sh treats --strict and --deep as independent flags. The handover checklist in the overnight plan spec invokes `./test.sh --strict`. But test.sh:220 reads "...is what `--deep` is for; the runbook's handover gate requires it before..." -- the runbook requires no such thing.

So the gate performance work (480s -> 152s) was justified on the strength of a guarantee that does not exist, and the executable D-030 recurrence test is not in the handover path.

FIX: --strict implies --deep. Fix the comment. Then negative-control it: mutate the implication and observe the deep marker disappear from the output. Note this interacts with think-osyp -- do not restore a byte-comparison of a non-portable trajectory scalar as part of "making deep run in strict".
