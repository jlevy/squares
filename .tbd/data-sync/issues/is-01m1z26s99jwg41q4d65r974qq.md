Observed while validating the explainer restructuring in think-8d1n: two figure-number comments in .github/workflows/pages.yml caused reachable_tests.py to select the entire test suite. Its .github prefix rule ignores diff semantics, and --run executes pytest -q tests -m not exhaustive_exact without xdist, including every slow test. The local run exceeded 17 minutes despite --jobs4 --inner-jobs2. Investigate a supported way to classify documentation-only workflow edits while preserving conservative coverage for executable workflow changes. Record validation-scope exceptions explicitly; do not hide or stash changed paths.

## Notes

The original standard pre-push run selected 45 steps and was deliberately stopped after 1,404.87 seconds: its whole-suite reachable-test step was still running serially with no observed test failure, while the other 44 steps passed. The selector treats any .github path as suite-wide and does not examine comment-only semantics; --push --skip cannot exclude its dynamically added reachable step. The follow-up honestly used the existing 44-step edit floor (all passed in 65.03 seconds) and select_tests on the six paper/code paths, separately confirming that the seventh path changes only two workflow comments and parsed YAML is unchanged. All 666 tests from the resulting 30 files passed in 38.72 seconds, including selected slow tests, using two xdist workers. PR #117 records this validation disposition. Leave this selector improvement open for a separate change.
