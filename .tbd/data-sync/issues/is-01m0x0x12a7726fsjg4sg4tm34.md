validate_schemas requires defect ids contiguous from D-001, so every branch must mint the next sequential D-NNN, and concurrent branches necessarily collide: PR 37 minted D-320/D-321 (stale synopsis aggregate; compound adjective) while the PR 33 branch independently minted D-320..D-328 for different defects. Same class as the H-042 collision that the research-ID reconciliation PR fixed. Standing resolution: whichever branch merges second renumbers its entries during the merge (contiguity forbids renumbering standalone). Note also the substantive overlap to reconcile at that merge: PR 37's D-320 and PR 33's D-328 are the same 98-vs-106 stale aggregate, fixed two different ways (validate-every-occurrence vs remove-the-copy); with the copy removed, the every-occurrence check passes trivially, so both fixes compose. Options if collisions should be prevented rather than reconciled: branch-provisional ids swapped at merge, or id reservation through the tbd sync store. Decide and document in conventions.
