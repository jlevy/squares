A decision rather than a defect, and it should be made deliberately rather than inherited.

`build_workbench_site.BANNER` injects a strip at the top of the published page: 'Prototype. This workbench is a retained spike, not project code: it is excluded from the repository's lint floor and its animation model is still moving. Figures it draws are not evidence. The explainer is the published work.'

**Half of that is already false.** As of the browser-floor work the page is not excluded from a lint floor -- its JavaScript and CSS are at zero under Biome, its script type-checks, and its gates run in `packing-validate`. What remains true is that the animation model is still moving and that figures it draws are not evidence.

Three questions, and they are separable:

1. Does the banner get rewritten to what is still true, or removed? Removing it is think-g0lh and waits on the rest of Phase 6; rewriting it is cheap and can go with the publish.
2. Does the explainer at `/` link to `/workbench/`? There is no link either way today except the banner's own link back to `/`. A page nobody can reach from the front door is published but not visible, which may well be what is wanted for now.
3. Is `/workbench/` meant to be shareable yet? It is public the moment it deploys, whatever links to it.

Whatever is decided, the banner's text is one constant in one file, so this is minutes of work once the answer is known.

## Notes

The false half is gone, as of 2e32c1a1. The banner no longer says the workbench is excluded from the lint floor or calls itself a prototype or a retained spike; it says the one thing still true -- the animation model is still moving, so a number it draws is not evidence -- and still links to the explainer.

The module docstring was tied to the same false claim and now separates the two conditions: where the code sits (still the spike tree, until Phase 6E) is a fact about the repository, not something a reader of the page needs warning about. The banner comes off when the animation model settles.
