The one glyph source in the explainer's PDF the project did not choose. `atlas/known-best/known-best-1-100.svg`, written by `packing/devtools/build_known_best_atlas.py`, sets 468 labels in `font-family="Helvetica, Arial, sans-serif"`, so the export carries nine Helvetica-Bold / Helvetica-BoldOblique subsets on macOS and would carry Liberation Sans on the Linux runner: the figure's text is a different face for every machine that draws it.

Accepted by the owner (2026-09-07): the figure is generated by its own pipeline, is published on its own, and stays as it is. This bead is the record of the exception rather than a request to change the figure, and it is what `ATLAS_FACES` in `packing/devtools/render_explainer_pdf.py` names, so the guard's one remaining exception has a bead like every entry `EXPECTED_HOST_FONTS` ever had.

Closing it would mean the figure draws its labels from a face the project ships -- `build_known_best_atlas.py` setting them in the print sans and the explainer declaring it for the SVG, or the labels converted to paths at build time. Only then is the export free of the reader's machine.

Note: the on-screen guard never sees these labels; the figure is an `<img>`, so its text is not a text node of the document. The PDF guard is the only place this is visible.

Raised by the senior engineering review of PR #134 (finding S134-R1).
