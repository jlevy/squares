Owner request 2026-10-10: the outer border box on packings, in the PDF and on the web, should have the same line thickness as the small squares. Two line widths have caused a lot of confusion where things do not look aligned.

Why it misleads: every stroke is centred on its edge (no inset, clip or paint-order), and the container is drawn under the squares. Where a square touches the wall, only part of the heavy outer stroke shows; in the gaps the full width shows. So the visible border thickness varies along each side, and boundary-touching squares look offset from the wall.

Renderers that differ today (origin/main 6038af33c):
- Atlas posters and explainer figure, packing/devtools/build_known_best_atlas.py: container SUMMARY_CONTAINER_STROKE = 1.15 (:223; outline :1926-1951; gray row reference :1913-1924) vs square stroke 0.42 (:1883). SUMMARY_OUTLINE_GAP (:224) is derived from the container stroke, so the layout arithmetic moves too.
- Site case pages, atlas tiles, thumbnails and logo, packing/devtools/render_frontier_page.py packing_svg :361-431: frame 1.2*unit (:412) vs squares 0.6*unit (:414); 12 vs 6 in the 1000-unit drawing files (:459-471). CSS overrides in site.css:3026-3047 (1.2/102 vs 0.6/102, non-scaling); row reference at site.css:2343-2360 and overview_sections.py:2794-2834.
- Workbench: --scene-frame-width: 4px (packages/workbench workbench.css:65, rule :365-372) vs 1.5px non-scaling square strokes (application.js:817-818, pack-panel.ts:195-196, animation-panel.ts:116-117).
- Packing-methods figures, packing_methods_figures.py: container 1.5 in #52667a painted on top of 0.75 #172b3a squares (:257-274), so the grey border covers the outer half of the square strokes.
